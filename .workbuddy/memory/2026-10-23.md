# 2026-10-23

## GithubSrcReader 基础框架搭建（Android / Compose + Miuix）

**目标**：查看 GitHub 云端代码 + 本地文件夹代码的阅读器，界面走 Miuix（澎湃/HyperOS）风格，底栏悬浮。

**技术栈**
- AGP 9.4.0（内置 Kotlin，不能应用 `org.jetbrains.kotlin.android`，否则构建报错）
- Kotlin 2.4.21 + Compose BOM 2026.09.00（compose 1.12.1）
- Miuix 0.9.4：`miuix-ui-android` / `miuix-icons-android` / `miuix-squircle-android`（blur 需 minSdk 33、preference/nav 暂未启用，已注释）
- OkHttp 4.12.0 + `org.json`（不引序列化插件）、Navigation Compose 2.9.7、documentfile 1.1.0

**关键坑（重要）**
1. Miuix 0.9.4 用 Kotlin 2.4 编译（metadata 2.4.0），AGP 9 内置 Kotlin 2.2.10 只能读到 2.3.0 → 必须升级编译器。
2. AGP 9 下不能 apply KGP 插件；正确做法是在根 `build.gradle.kts` 的 `buildscript.dependencies` 加
   `classpath("org.jetbrains.kotlin:kotlin-gradle-plugin:2.4.21")`，内置 Kotlin 的版本由此决定。
3. Miuix 0.9.4 依赖 compose 1.12.x，BOM 必须 ≥ 2026.09.00，否则运行期不匹配。
4. Miuix 的 `FloatingNavigationBar` 会把传入的 modifier 应用在内部 Row 上，不能直接用它做 Box 对齐；
   需要在外面套一层 `Box(Modifier.align(BottomCenter))`。

**结构**
```
data/  model/(Models, Language, CodeSource) github/(GitHubUrlParser, GitHubApi, GitHubCodeSource)
       local/LocalCodeSource(SAF) TextReader AppPreferences
ui/    code/(CodeTokenizer, CodeBlock, CodeColors) theme/Theme.kt
       components/(AppBottomBar, FileRow) screens/(Home, Browse, Viewer, Settings)
       AppViewModel AppUiState AppRoot MainActivity
```
- 源码统一抽象 `CodeSource`（list/readText），GitHub 与本地文件夹共用浏览/阅读界面。
- 顶部栏用 `SmallTopAppBar`，底栏用 `FloatingNavigationBar`（悬浮），Viewer 路由隐藏底栏。
- 语法高亮为手写词法扫描（CodeTokenizer），只输出 token 区间，着色在 Compose 层做，支持 Kotlin/Java/Python/JS/TS/Go/Rust/C/C++/C#/Swift/SQL/JSON/YAML/XML/HTML/CSS/Markdown 等。

**验证**：`./gradlew :app:assembleDebug` 通过；`testDebugUnitTest` 12 个用例全绿（URL 解析 7、词法 4、示例 1）。

## 迭代：代码预览双指缩放 + release 签名打包

- `CodeBlock` 新增双指缩放：`zoom` 用 `rememberSaveable` 保存，范围 0.7x~3.0x；
  实现方式是**按 zoom 重算 fontSize/lineHeight**（13sp/19sp × zoom），而不是 graphicsLayer 缩放——
  文字始终按原生分辨率渲染不糊，且滚动范围会跟着内容自动更新。
- 手势：外层 Box 用 `awaitEachGesture` + `awaitPointerEvent(PointerEventPass.Initial)`，
  **只在 changes.size > 1 时** `calculateZoom()` 并 consume 多指事件；单指拖动仍交给内层
  `verticalScroll/horizontalScroll`，Initial 阶段先于子节点消费可避免缩放时滚动抖动。
- `LaunchedEffect` 的跳转定位改用 sp 换算（`(19f*zoom).sp.toPx()`，兼容系统字体缩放），并把 zoom 加入 key。
- release 打包：新增 `keystore/githubsrcreader.jks`（CN=GithubSrcReader，10 年有效期），
  签名信息读根目录 `keystore.properties`（已加入 .gitignore）；`app/build.gradle.kts` 里
  `signingConfigs.create("release")`，文件缺失时降级为不签名，不会卡住别人的构建。
- AGP 9 的 `buildTypes.release` 用 `optimization { enable = false }`（旧的 `isMinifyEnabled` 已不适用）；
  本次**未开 R8**，release 30MB（dex 29MB），需要更小包时可把 `optimization.enable` 改 true。

## 迭代：工具栏路径与下载文件名

- 问题 1：预览页顶部把路径塞进 `SmallTopAppBar(subtitle = path)`。Miuix 的 subtitle 只有一个裸 `Text`
  （没有 maxLines/overflow，宽度还被限制在 title 区约 55%），长路径换行把工具栏从 52dp 撑到 90dp+。
  修法：不再用 subtitle，改用 `bottomContent` 放一行 `PathLine`（11sp、`maxLines = 1`、
  `TextOverflow.MiddleEllipsis`，需 `@OptIn(ExperimentalTextApi::class)`），高度恒定 ~68dp 且能吃满宽度。
- 问题 2：`Main.kt` 存成 `Main.kt.txt`。根因在 AOSP `MediaProvider.ensureFileColumns` →
  `FileUtils.splitFileName(mimeType, displayName)`：它把 MIME 反推成规范扩展名，和文件名扩展名对不上就追加
  （`text/plain` → `txt`）。所以保存 MIME 不能自己拍，只能返回「系统 `MimeTypeMap` 为该扩展名认的 MIME」
  （`getMimeTypeFromExtension`），查不到（kt/kts/gradle…）就回退 `application/octet-stream`——
  此时系统认为扩展名未知，走 `mimeTypeFromExt == mimeType` 分支原样保留文件名。
  AOSP 单测 `FileUtilsTest.testBuildUniqueFile_unknown` 印证了 octet-stream 保留原扩展名。
- `ExternalFiles.mimeForSave` 改成可注入 `mimeLookup`，纯 JVM 单测覆盖「查表命中 / 未命中回退 / 无扩展名」，+2 用例（共 70）。
- `FileDownloader.save` 落盘后再查一次 `DISPLAY_NAME` 拼提示路径，避免 OEM 改写文件名时提示与实际不符。

## 迭代：缩放保持 + 横屏紧凑布局

- 缩放状态原来在 `CodeBlock` 内部的 `rememberSaveable` 里：刷新时 `when(content)` 切到 Loading 分支，
  `CodeBlock` 被移出组合，状态跟着丢。改成**由屏幕持有**：`ViewerScreen` 里
  `var zoom by remember(state.path) { mutableFloatStateOf(1f) }`，`CodeBlock(zoom, onZoomChange)` 变成受控组件。
  reload 只换内容不重建屏幕 → 缩放保留；退出预览 / 重新进入 / 换文件 → 组合重建，回到 1f。
- 顺手修掉一个老毛病：`LaunchedEffect` 原来把 `lineHeightPx` 当 key，双指缩放会重新执行定位、
  把视图拽回顶部（无 targetLine 时）或目标行。改为只用 `(text, targetLine)` 作 key。
- 横屏适配：`LocalConfiguration.screenHeightDp < 480` 判为紧凑布局（横屏手机 / 分屏都会命中，竖屏手机不会），
  紧凑时省掉路径行 `PathLine`、`FileMeta`（仅在截断 / 跳转行号时才显示）、代码区 padding 12→6、圆角 18→12，
  代码可视高度约 +16%。没用 `BoxWithConstraints`，避免多一层 subcomposition。

## 修复：底栏「有时点了没反应」（回不了首页）

- 走查结论：底栏视觉面积比可点面积大不少 —— 外层 squircle 52dp 高，里面四个胶囊只有 40dp，
  上下 6dp 留白 + 胶囊之间 `Arrangement.spacedBy(4.dp)` 的缝隙全都不响应点击；
  更糟的是这些区域**不吃事件**，点击会漏到下面的列表上，可能误开文件/误进目录。
- `AppBottomBar` 重构成「热区撑满整条栏」：外层 Row 固定高 `BarItemHeight + BarInset*2`，
  每个分区是 `fillMaxHeight()` 的 Box（点击热区含上下留白），间距改成 Box 里的 `padding(horizontal = 2.dp)`
  包进热区，视觉胶囊仍是 40dp 高、同心圆角不变；外层再挂一个 `detectTapGestures {}` 吞掉剩余留白的点击，杜绝漏到列表。
- 顺带修一个真实竞态：`openUrl`/`openLocalTree` 的协程跑完才发 `OpenBrowser`，
  慢网络下用户中途切到首页，响应回来会把人又拽回浏览页（表现就是「点了首页又跳回去」）。
  现在打开任务存到 `openJob`，切分区先 `viewModel.cancelPendingOpen()`；取消时把 `busy` 复位，不弹错误。
- `AppRoot`：底栏容器加 `zIndex(1f)`；`popUpTo` 改用 `findStartDestination().id`，并跳过「已在该分区」的重复 navigate。

## 修复（第二次）：首页 ↔ 浏览页切不动

- 上一轮把「底栏热区比可见栏小」当成主因，用户反馈没解决 —— 那条确实是个真缺陷（点击会漏到列表），但不是这个 bug。
- 新线索：**目录深时切不动，退几层目录后又正常**。说明和「时间/某次状态刷新」有关，不是纯触摸命中。
- 定位到 `AppRoot` 的底部导航选项：`popUpTo(start){saveState = true}` + `restoreState = true`。
  读 `navigation-runtime 2.9.7` 的 `NavControllerImpl.executePopOperations` 后确认：
  `saveState` 时（即使一个条目都没弹）都会执行
  `generateSequence(foundDestination).takeWhile{ !backStackMap.containsKey(it.id) }.forEach { backStackMap[it.id] = savedState.firstOrNull()?.id }`
  ——也就是会把「被弹掉的浏览页」挂到 **popUpTo 目标（起始页 HOME）的 id** 下。
  之后带 `restoreState` 回首页时，`restoreStateInternal(HOME)` 会把这些条目**当首页的栈恢复**，
  于是「点首页 → 又回到浏览页」；`backStackMap` 又被 `restoreStateInternal` 清掉，下次再重新挂上，
  形成「有时好有时坏」的抖动。平铺的四个 destination 尤其容易踩（官方示例用嵌套图规避）。
- 结论：底栏切分区**不要**用 saveState / restoreState。四个页面的 UI 状态本来就在 ViewModel
  （`_home.urlInput`、`_browse.path/entries`），回来自然还在原目录，不依赖这套机制。
  现在：`navigate(tab.route) { popUpTo(findStartDestination().id); launchSingleTop = true }`。
- 同时去掉 `if (tab.route != route)` 守卫：`route` 只是渲染快照，拿它做导航守卫会把切换卡死；
  popUpTo + singleTop 本身幂等。
